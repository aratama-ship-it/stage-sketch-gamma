# 環境設定の全体リセット: GitHub Pages 公開前の確認記録

## 対象と比較元

- 比較元: `aratama-ship-it/stage-sketch-gamma` の公開版 0.2.5、`ac19f20`。公開候補は 0.2.6。
- 対象: 環境設定の赤い「リセット」の確認入口と、この端末に保存した舞台スケッチのデータ削除処理。
- 既存版は `window.confirm` を2回呼ぶ。利用者の Codex ブラウザではボタンを押しても確認画面が出ないと報告された。ブラウザ側で確認が表示されない理由は未特定。
- ショーの保存形式、読み込み、自動保存、書き出し、音楽再生、共有の通常経路は変更していない。今回のコード変更は、明示的な全体リセットを実行するときだけ保存領域へ書き込む。

## 防止策

- ブラウザ標準の確認画面に依存せず、アプリ内に2段階の確認を表示する。最終段階の「ショーと設定を削除」を押す前には削除しない。
- 誤操作を避けるため最初のフォーカスは「やめる」に置き、Esc、閉じる、背景クリックでも取り消せる。
- 削除対象は既知の舞台スケッチ保存鍵と `gamma:` 領域に限定する。バックアップの復元抑止印を保存できたことを確認してから再読み込みする。
- 保存領域へのアクセスや削除に失敗した場合は再読み込みせず、画面内に失敗を表示する。一部削除の可能性も明示する。
- JavaScript/CSS の参照版と Service Worker キャッシュ名を更新し、古い画面との混在を減らす。

## 検証結果

- 同梱「テスト: 全機能の試験場」の **0-1** を隔離したローカル配信で開き、赤いリセットから第1・第2確認が表示されること、「やめる」で元の環境設定へ戻り、試験場のショーが残ることを Codex ブラウザで確認した。旧候補では Esc でも取り消しを確認した。
- `node --test tests/feature-test-show.test.mjs tests/stage-reset.test.mjs tests/stage-project-store.test.mjs tests/bundled-sample-timing.test.mjs`: 35件すべて成功。リセットのテストは試験場 0-1 の同梱データを使い、対象鍵だけの削除、無関係な鍵の保持、復元抑止印、音源DB削除要求、再読み込み、削除失敗時の停止を検査した。
- `node --check stage-sketch.js`、`node --check stage-sw.js`、`git diff --check`: 成功。
- 変更した試験場の生成スクリプトから JSON とローダーを再生成し、差分が 0-1 の手順追記だけであることを確認した。

## 未確認と運用上の境界

- 実ブラウザでの最終削除は、利用者のショーを保護するため実行していない。削除分岐はメモリ上の保存領域で検査した。
- Safari、スマートフォン、別タブが同時に開いた状態での操作、音源 IndexedDB の実削除完了は未確認。音源DB削除要求は非同期で、接続中は完了が遅れる場合がある。
- 利用者の公開タブの JSON 書き出し完了は確認できていない。書き出しが完了するまでは、実データのリセットを行わない。
- `gamma-dev/feature-test-show/verify.cjs` は公開リポジトリの追跡対象に含まれず、隔離した配布候補には無いため実行していない。代わりに上記の同梱ショーテストとブラウザ操作を実施した。
- 保存形式は変えていないため旧版の読み込み互換性は維持される。コードを戻しても、利用者が完了したリセットによって削除されたデータは復元できない。
